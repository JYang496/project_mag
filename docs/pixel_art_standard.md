# MagArena 像素美术规范

本文档是美术制作、运行时接入和验收的共同约定。代码中的尺寸常量以
`res://Visual/pixel_art_policy.gd` 为运行时权威来源；当本文与代码不一致时，
先核对实际消费者，再同步修正文档，不要凭旧稿推断尺寸。

## 统一方向

- 目标风格是冷色工业科幻竞技场：硬边轮廓、清晰明暗块和有限高亮。
- 角色、敌人、地形、特效与 UI 图像都必须落在稳定像素网格上。
- 青色用于系统能量、磁场和结构信息；橙色用于主要操作；红色用于危险；
  绿色用于成功反馈。稀有度颜色独立于这套语义色。
- 同一对象的正背面、动画帧和状态变体应保持相同光源方向、轮廓厚度、
  色阶关系和脚底锚点。
- 不用平滑缩放、抗锯齿边缘或半透明杂边来掩盖轮廓问题。

## 画布与角色规格

- 逻辑画布：1280 x 720；窗口使用整数拉伸。
- 玩家机甲源帧：128 x 128，透明留白属于帧锁定的一部分。
- 玩家实际战斗视觉占位：96 x 96 逻辑像素。当前运行时按 128 像素参考高度
  统一缩放到该占位；不得借美术替换改变碰撞体、移动或攻击几何。
- Ranger 的正面资源使用 `bottom` 命名，背面资源使用 `top` 命名；这是现有
  运行时方向约定，不因文件名偏好而重命名。
- Ranger 移动动画为正、背面各 8 帧、10 FPS、循环播放。双腿收拢、双臂自然
  下垂；悬浮反馈只使用青色磁场线，不加入火焰尾焰。
- 所有移动帧必须使用同一 128 x 128 网格，主体中心、脚底基线和透明边距不漂移。

## 其他资产角色

- 普通敌人帧：32 x 32；精英敌人帧：48 x 48。
- 普通掉落帧：32 x 32；大型掉落帧：64 x 64。
- 小、中、大特效帧：32 x 32、64 x 64、128 x 128。
- 火焰喷射帧：256 x 80；冰霜喷射帧：256 x 90。
- 模块图标：32 x 32；甲板单元和大型场景道具：256 x 256。
- 武器的当前素材、逻辑和已批准展示尺寸保持不变，除非后续任务明确授权。
- 角色血条与热量槽 HUD 保持不变；美术统一不能借机重排或重绘这些组件。

## 图像制作规则

- RGB 与 Alpha 必须共享同一像素网格；非刻意柔化的透明像素应完全透明。
- 保留有意的色阶，清理肉眼不可区分的近重复颜色和意外抗锯齿。
- 保持宽高比。不要拉伸主体去填满方形画布，透明边距应有明确用途。
- 动画先锁定画布、主体锚点和方向，再逐帧调整动作。
- 大图预览只能使用整数倍最近邻放大，预览文件不是运行时权威资产。
- 已批准资产不得因出现相似候选图而直接覆盖；先证明运行时目标，再决定接入。

## Godot 接入规则

- 运行时 `Sprite2D`、`AnimatedSprite2D` 和像素 UI 图像使用最近邻过滤。
- 像素角色与 UI 图像默认关闭 mipmap；导入设置需在接入时复查。
- 场景中的显示尺寸可以按项目策略从源帧统一换算，但最终逻辑占位必须是整数。
- 替换或新增资源后，应检查 `.tscn`、`.tres`、定义资源和脚本常量中的全部有效绑定，
  并搜索仍在运行时生效的旧路径。
- 纯视觉修改不得改变碰撞形状、脚本数值、攻击范围、移动速度、掉落或存档数据。

## 验收清单

1. 在真实游戏尺寸检查轮廓、方向、脚底锚点和前景可读性。
2. 在整数倍放大预览检查像素网格、Alpha 边缘、色阶和逐帧漂移。
3. 确认每个方向的帧数、帧率、循环方式与运行时资源一致。
4. 确认最近邻过滤、mipmap 策略、整数逻辑占位和宽高比。
5. 确认视觉变化未改变碰撞与玩法几何，也未修改受保护的武器、血条或热量槽 HUD。
6. 运行对应聚焦测试、启动资源清单检查（如目录内容发生变化）和 Godot
   `--headless --check-only --quit`。
7. 每个独立美术工作包提供可直接启动的 `tests/showcases/<domain>/` 场景，
   同时显示关键状态与实际尺寸，并记录入口和查看说明。
