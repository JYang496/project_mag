# MagArena 玩法界面与休息区优化工作计划

日期：2026-08-13  
状态：待实施  
范围：奖励卡、战斗 HUD、歼灭协议用语、大额金币反馈、休息区引导与导航  
不在本期：经济平衡、敌群节奏重构、前期金币合并、新手难度调整

## 1. 已确认的设计约束

1. 保持“从玩家熟悉的射击/割草玩法开始，再逐渐介绍协议、棋盘、模块等特色系统”的渐进教学方向。前期不为了展示特色而额外增加决策节点。
2. 歼灭协议中的多个刷新分段是当前怪物强度的分割，不是给玩家喘息的传统波次。保持连续紧张感，不加入清场停顿、波次庆祝、时间冻结或强制间歇。
3. 保留大量小金币掉落和收集形成的爽感。当前不合并前期小金币；只为 5、10 金币增加更明确的大额表现。待数值和密度演进到必要阶段后，再单独评估条件式合并。
4. 武器定位摘要只描述武器类别和直接定位，不添加玩法指导、使用建议或“应该如何打”的后半句。
5. 生命值始终使用同一种主色，不以橙色、红色切换表示危险。危险状态使用同色脉冲、描边/亮度变化和警告反馈。
6. 正常玩家可以通过实际游玩学习敌群安全距离和操作节奏，本期不因自动操作结果调整前期难度或额外增加生存教学。
7. 经济系统优化进入未来计划，本期不调整产出、价格、刷新成本或消耗出口。

## 3. 工作流 A：奖励卡信息层级与定位摘要

### 目标

让玩家先识别武器类别和定位，再阅读机制与数值；提高 1280×720 和窗口化场景下的正文可读性，同时避免文案教玩家具体打法。

### 文案规则

新增独立字段 `role_summary`，不复用 `summary_text`、`detail_role` 或 `outcome_text`。

格式限制：

- 中文建议 4–10 字，最多一行。
- 只保留一个定位短语，禁止使用中点后的用途指导。
- 不写“保护移动空间”“优先清除”“适合处理”等指导性结果。
- 不写数值、不写操作命令、不评价强弱。

首批定位摘要建议：

| 武器 | 定位摘要 |
|---|---|
| 机枪 | 中距离持续火力 |
| 激光 | 中距离精准光束 |
| 轨道卫星 | 近身自动防御 |
| 霰弹枪 | 近距离爆发 |
| 狙击枪 | 超远距离重击 |
| 火焰喷射器 | 近距离持续范围伤害 |
| 火箭发射器 | 远距离范围爆破 |
| 冰川投射器 | 范围减速控制 |
| 冲刺刃 | 高机动穿刺 |
| 电浆长矛 | 直线贯穿伤害 |
| 加农炮 | 低频重击 |
| 电锯发射器 | 中近距离持续切割 |
| 充能爆能枪 | 蓄力爆发 |
| 手枪 | 灵活稳定输出 |
| 长矛 | 近战穿刺控制 |

最终名称须与武器目录实际显示名核对，不能在本地化表中创造与现有命名不一致的别名。

### 布局改动

1. 在武器名/等级下新增单行定位摘要，字号 15–16 px，使用现有主文本色或系统强调色，不使用稀有度色。
2. 武器名目标字号 18–20 px；机制正文 14–15 px；关键属性 14 px；徽章和标签维持 12–13 px。
3. 定位摘要固定一行、超长省略；中文与英文都必须在三列布局中不换行。
4. 机制正文限制两行。详细机制继续由现有详情数据承担，不在卡面增加新段落。
5. 标签最多显示三个；不要用新增摘要换取卡片总高度增长。
6. 通过小幅压缩武器 hero 区、重复类型文案和空白间距腾出摘要空间，维持奖励选择区域约 382 px 的现有高度。
7. 武器升级卡的摘要使用同一武器定位，不自动生成“如何使用”的升级建议；升级差值仍由现有比较区表达。

### 主要修改点

- `UI/scripts/presentation/reward_card_data_assembler.gd`
- `UI/scripts/reward_selection_panel.gd`
- `UI/scripts/presentation/reward_card_model.gd`（若显示模型为强类型字段）
- `data/localization/game_content.csv` 或现有武器本地化源

### 验收标准

- 1280×720 下三张武器卡无需纵向滚动。
- 中英文武器定位均保持单行且不与等级、徽章重叠。
- 玩家在只看武器名和定位摘要时能区分三张卡的基础定位。
- 定位摘要中不存在指令、推荐目标、构筑建议或玩法教学语气。

## 4. 工作流 B：生命值同色危险脉冲

### 目标

主生命条始终保持当前正常青色，以节奏和亮度表达危险，不改变生命颜色语义。

### 状态规则

1. 正常：生命比例大于 35%，保持现有青色填充和稳定描边。
2. 警告：生命比例小于等于 35%，填充色仍为同一青色；外框和填充高光进行低频脉冲。
3. 危急：生命比例小于等于 18%，颜色仍不变；提高脉冲频率和幅度，并在首次跨越阈值时触发一次明确的视觉警告。
4. 跨越 35%/18% 的现有警告音继续保留，不重复叠加另一条循环音效。
5. 治疗回到阈值以上时立即降级或停止脉冲；不能残留 tween。
6. 暂停、死亡、离开战斗、重新生成 HUD 时清理脉冲状态。

### 推荐视觉参数起点

- 警告态：约 1.8 Hz；外框 alpha 在基础值与 +0.16 之间变化；线宽增量不超过 0.75 px。
- 危急态：约 3.0 Hz；外框 alpha 增量不超过 0.28；增加一次 0.18 秒同色亮度冲击。
- 不缩放整块 HUD，避免生命条位置抖动。
- 不使用红色、橙色或全屏持续闪烁。

### 主要修改点

- `UI/scripts/components/player_status_hud.gd`
- 保持 `Player/Mechas/scripts/player_damage_feedback_controller.gd` 的阈值警告逻辑

### 验收标准

- 100%、35%、34%、18%、17%、0% 六个边界状态下填充色保持同一色相。
- 脉冲只在对应危险区间运行。
- 快速受伤/治疗跨越阈值不会创建重叠 tween 或残留闪烁。
- 生命轨道在 0%、接近满值和满值时仍清楚可见。

## 5. 工作流 C：歼灭协议“波次”改为“强度”

### 目标

让玩家理解分段代表连续战斗中的强度推进，而不是会带来喘息时间的传统波次。

### 文案范围

玩家可见的歼灭协议文本统一替换：

- `波次 {current}/{total}` → `强度 {current}/{total}`
- `Wave {current}/{total}` → `Intensity {current}/{total}`
- 战斗引导中的单位 `waves/波次` → `intensity/强度`，英文最终用词需统一为 `Intensity` 或 `Intensity Stage`，全项目只选一种。
- 协议卡的 `3–5 批次` 可保留“批次”，因为它描述预算分割；若与 HUD 认知不一致，再统一为“3–5 段强度”。

不修改内部变量和运行时 API：

- `current_batch`
- `total_batches`
- `release_contract_next_batch()`
- 生成器内部的 batch/wave 命名

内部术语仍服务实现；本期只调整玩家可见语义，避免扩大回归面。

### 反馈规则

- 强度提升时不暂停、不冻结、不清屏、不播放胜利提示。
- 可在现有左上协议 HUD 上做一次不超过 0.25 秒的边框亮度强调，但不是本项必须条件。
- 不改变 `early_release_ratio`、12 秒兜底或任何敌群释放参数。

### 主要修改点

- `data/localization/ui_texts.csv`
- `UI/scripts/components/battle_contract_hud_presenter.gd` 中英文 fallback

### 验收标准

- 中文歼灭 HUD 不再出现“波次”。
- 英文歼灭 HUD 不再出现 `Wave`。
- 生存、追击或其他确实表达敌潮的协议文本不做全局机械替换。
- 敌人释放节奏与修改前完全一致。

## 6. 工作流 D：5/10 金币大额表现

### 目标

保留大量 1 金币的密集收集体验，同时让 5、10 金币具有明确的视觉和听觉层级。

### 表现规格

| 面额 | 尺寸起点 | 视觉层级 | 拾取反馈 |
|---|---:|---|---|
| 1 | 1.0× | 维持现状 | 维持现状 |
| 5 | 1.25× | 更亮轮廓或双层小光圈 | 独立音高/音色，显示 `+5` |
| 10 | 1.5× | 金白核心和明显外环 | 更强但短促的音效，显示 `+10` |

约束：

- 不减少 1 金币数量，不在本期做合并。
- 不只依赖尺寸区分；至少增加轮廓、核心亮度或动画节奏中的一个通道。
- 大额金币亮度不得压过危险预警和精英攻击提示。
- 不改变金币价值和掉率。

### 主要修改点

- `Objects/loots/coin.gd`
- `Objects/loots/coin.tscn`
- 金币拾取音效/浮字所属组件
- `UI/scripts/components/gold_hud_display.gd`（只在需要区分大额脉冲时）

### 验收标准

- 静止截图中可区分 1、5、10 金币。
- 快速移动和密集掉落时仍可识别 5、10 金币。
- 1 金币的现有密集爽感与拾取频率保持不变。

## 7. 工作流 E：休息区引导、服务状态与整备清单

采纳原建议 8A、8B、8D、8E、8G。

### E1. 首次进入的空间认知（8A）

现有 `RestAreaArrivalPresenter` 已包含校准、服务上线和交互锁定流程。基于它扩展，不新增第二段独立过场。

实施：

1. 首次进入休息区时，在现有服务上线阶段依次强调采购、强化、仓库、棋盘和协议入口。
2. 总新增时长控制在 3–5 秒内，尽量复用现有到达动画时间线。
3. 强调方式采用设备/区域点亮和名称标签，不移动玩家、不弹模态教学。
4. 仅首次进入或服务首次解锁时完整播放；普通章节休息沿用短版到达反馈。
5. 首次展示状态纳入现有存档体系，避免仅依赖节点内临时变量。

主要所有者：

- `UI/scripts/components/rest_area_arrival_presenter.gd`
- `World/rest_area.gd`
- `World/rest_area_hint_presenter.gd`
- `SaveManager` 对应的设置/进度保存接口

### E2. 靠近提示包含服务名和用途（8B）

现有区域提示已经能提供服务名称、可升级数、暂存模块数和棋盘状态，但场景标签目前被压缩为单行标题。

实施：

1. 常态远距离场景标签保持单行服务名，避免九宫格拥挤。
2. 悬停、选中或角色到达区域后，展开为两行：
   - 第一行：输入提示 + 服务名；
   - 第二行：一句用途或当前状态。
3. 示例：
   - `[LMB] 武器采购` / `购买武器与模块`
   - `[LMB] 强化工坊` / `2 项可升级`
   - `[LMB] 仓库` / `1 个模块待处理`
   - `[LMB] 棋盘管理` / `安装格子效果与任务模块`
4. 不可用服务显示具体原因，不静默拒绝；采购未开放时显示“完成第 3 场战斗后开放”。
5. 输入标签必须从 InputMap/现有本地化获取，不硬编码键位。

主要所有者：

- `World/rest_area_hint_presenter.gd`
- `World/rest_area.gd`
- `data/localization/ui_texts.csv`

### E3. 管理界面内 Q/E 快速切换服务（8D）

服务顺序固定为：

`采购 → 强化 → 仓库 → 棋盘 → 启动协议`

实施规则：

1. 只在休息区且主服务菜单/管理页打开时响应 `SWITCH_LEFT`、`SWITCH_RIGHT`。
2. 优先复用项目已有 Q/E 输入动作，不新增键位。
3. 如果当前存在阻断模态框、未确认替换、分支选择或未提交棋盘编辑，禁止切换，并显示原因。
4. 无待提交状态时，关闭当前服务层并打开目标服务；不重新播放完整入场动画。
5. 完整商店未开放时，切换到采购仍显示不可用原因，不自动跳过该服务，保持顺序可预测。
6. 管理界面顶部显示 `Q 上一服务 / 当前服务 / 下一服务 E`；使用本地化输入名称。
7. 退出管理界面后，玩家仍位于当前服务对应区域；如现有空间与 UI 状态无法安全同步，第一版可先保持玩家位置不变，但必须保证选中区、高亮和菜单语义一致。

主要所有者：

- `UI/scripts/management/rest_area_ui_controller.gd`
- `UI/scripts/management/rest_area_primary_menus_view.gd`
- `World/rest_area_menu_bridge.gd`
- `World/rest_area.gd`
- `UI/scenes/runtime/rest_area_primary_menus.tscn`

### E4. 整备清单（8E）

清单是非强制提醒，不是任务列表。只显示有客观数据依据的事项。

首版项目：

- 未领取/未确认的强制奖励；
- 未选择的武器进化分支；
- 暂存模块数量；
- 可负担升级数量；
- 棋盘待提交修改；
- 可以进入下一协议。

不纳入：

- 是否浏览过商店；
- 是否花完金币；
- 是否采用系统推荐构筑；
- 任何主观“最佳操作”。

显示规则：

1. 位于休息区右上角或不遮挡服务标签的安全区。
2. 默认最多显示 4 行；无待办时折叠为“整备完成”。
3. 阻断项与可选项在图标语义上区分，不能都用感叹号。
4. 数据变化时局部更新，不反复播放整块入场动画。
5. 打开二级管理面板时可降低清单透明度或暂时折叠，避免与详情争夺注意力。

优先复用数据源：

- `TaskRewardManager`
- `InventoryData.temporary_modules`
- `PlayerData` 武器与金币
- `CellEffectRuntime`
- 现有分支选择阻断状态
- 棋盘编辑控制器的 dirty/pending 状态

### E5. 返回层级一致性（8G）

现有控制器已有分层取消逻辑，本项以验证和修正边界为主。

统一规则：

1. 第一层：关闭最上层确认/选择模态框。
2. 第二层：从具体管理页返回当前服务主菜单。
3. 第三层：关闭服务主菜单，返回休息区移动。
4. 一次取消输入不得跨越两层。
5. 返回后保留合理的分页、滚动位置和选中项；离开整个服务后可以清理临时 hover。
6. 退出服务时必须恢复 `PlayerData.is_interacting`、世界点击和区域导航。
7. Q/E 切换和 ESC/右键返回共享同一套关闭/提交检查，不能形成旁路。

主要所有者：

- `UI/scripts/management/rest_area_ui_controller.gd`
- `UI/scripts/management/modal_ui_controller.gd`
- `World/rest_area_menu_bridge.gd`
- 各管理页现有取消接口

## 8. 实施顺序

### 阶段 1：低风险语义与卡片可读性

1. 新增武器定位摘要数据与本地化。
2. 调整奖励卡信息层级和字号。
3. 将歼灭协议玩家可见“波次”替换为“强度”。

完成条件：奖励卡和协议 HUD 在 1280×720 中英文下通过视觉检查，战斗逻辑无变化。

### 阶段 2：战斗反馈

1. 将生命填充固定为同一青色。
