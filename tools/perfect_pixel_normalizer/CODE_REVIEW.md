# perfectPixel 代码评价

审查基准：`theamusing/perfectPixel` 的 `main` 分支提交
`72096de5cf1bff9102687c4f89af6f62c4273a86`。

## 结论

这是一个算法目标明确、效果展示直观的早期图像处理库，适合个人工作流、原型和
可人工复核的批处理；尚不适合作为无人值守生产管线的唯一质量门。

## 优点

- FFT 周期估计、Sobel 边缘对齐、网格单元采样三阶段设计与问题匹配。
- 同时提供 OpenCV 和 NumPy 后端，部署选择灵活。
- 支持自动网格、手动网格、三种采样策略及 ComfyUI 集成。
- 公共 API 小而直接，PyPI 已提供 0.1.4 通用 wheel。

## 主要问题

1. 仓库没有自动化测试和 CI，算法回归、跨平台打包及边界输入缺少保障。
2. `pyproject.toml` 是 0.1.4，而包内 `__version__` 仍是 0.1.2。
3. API 文档声明输入为 RGB，但 OpenCV 后端灰度转换使用 `COLOR_BGR2GRAY`。
   这不会交换输出颜色，却会用错误的通道权重进行网格检测。
4. 自动检测失败时返回 `(None, None, 原图)` 并通过 `print` 报告状态，
   不利于 GUI、服务端或批处理做结构化错误处理。
5. `fix_square` 在宽高只差一格时会删除或复制首行/首列；这是有损启发式规则，
   可能改变非方形构图。
6. 多处参数和阈值是硬编码经验值，缺少置信度分数和检测诊断信息。
7. OpenCV 与轻量后端存在大段重复实现，后续容易行为漂移。
8. 仓库与 PyPI 元数据声明 MIT，但审查的提交中没有独立 `LICENSE` 文件，
   再分发前应向作者确认完整许可文本。

## 本地封装的处理

- 固定依赖到 `perfect-pixel 0.1.4`，避免静默升级改变结果。
- GUI 将自动检测失败转为明确错误，并引导用户填写手动网格。
- 参数在进入算法前进行范围校验。
- 默认使用抗噪声更好的 `median`，同时保留另外两种采样。
- 输出统一为 PNG，并只使用最近邻整数倍率放大。
- 加入透明通道保留、批量处理、后台线程和基础回归测试。
